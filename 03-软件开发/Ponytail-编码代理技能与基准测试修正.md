# Ponytail：编码代理技能与基准测试修正

Ponytail 是一个开源技能，指导 AI 编码代理像“房间里最懒惰的资深开发者”那样行事。该项目自 2026 年 6 月 12 日发布以来，GitHub 星标已超过 82000，成为今夏增长最快的存储库之一，主要面向解决代理过度实现功能的问题。

## 核心机制

- 在代理上下文中注入一套规则，在编写代码前强制执行决策流程：
  - 功能是否真的有必要存在？
  - 代码库中是否已有现成的实现？
  - 标准库是否已提供该功能？
  - 平台原生功能是否已覆盖该需求？
  - 已安装的依赖项是否能解决该问题？
  - 能否用一行代码实现？
- 只有在回答完上述问题后，才编写能正常运行的最小代码量。
- 规则明确排除了在问题理解、信任边界输入验证、防数据丢失错误处理、安全性和无障碍性方面偷工减料，任何简化都需通过注释注明上限值和升级路径。
- 可安装在十余种代理平台上，包括 Claude Code、Codex、Cursor、GitHub Copilot、Gemini CLI 和 Aider。

## 基准测试争议与修正

最初的单次基准测试声称代码量减少 80% 至 94%。Scott Logic CTO Colin Eberhardt 深入分析后发现，该存储库实际上只是一个约 100 行的 Markdown 文件，重述了 20 世纪 90 年代的 YAGNI 原则，而且用一句“遵循 YAGNI 原则，用一行代码解决”反而在原始基准测试中超越了 Ponytail。Hacker News 上也有怀疑者认为整个项目只是规则加海量模板代码，甚至被质疑为“新版 leftpad”。

作者随后用公平的代理型基准重新构建了测试：在真实的 FastAPI + React 存储库上通过 Claude Code 运行十二项功能开发任务，并公开修正了此前的主张。更新后的 README 显示：

- 代码量平均减少约 54%；仅在代理过度构建时达到 94%，在代码本已极简时接近零。
- 成本降低约 20%，执行速度提高 27%。
- 简单提示词“编写一行代码”缺少 Ponytail 保留的安全防护机制。
- 先前数据是按任务计算的上限值，被错误报道为平均值。

Eberhardt 对此回应表示：“我很高兴他们对批评做出了积极回应。”

## 实践采用与深层意义

实践者正在将 Ponytail 用于代码审查。红帽公司杰出工程师 Max Rydahl Andersen 分享了工作流：使用 Hunk（终端差异查看器）与 Ponytail 进行代码审查，让代理找出过度设计并提示删除，通过代码形式反馈而非冗长文本。评论区还出现了与 herdr 等工具组合使用进行群体审查的模式。

Eberhardt 指出，技能和提示词框架大量涌现，但缺乏评估标准。Ponytail 项目在受到外部批评后修正基准测试，现在包含行为测试框架和公开的重现路径。这或许才是更具持久价值的贡献：不是 YAGNI 原则，而是期望技能必须证明其主张。
