# AI Coding 工程师价值与 Harness 之争

## 背景

2026 世界人工智能大会期间，InfoQ 媒体直播间围绕“AI 正在重写什么”探讨 AI Coding 带来的深层变化。嘉宾：Sirius contributor 滕昱、前 Google 软件工程师/月之暗面开发者关系唐飞虎。

## 核心共识

- AI 正在优先放大资深工程师的经验和判断能力。
- 真正受冲击的是：依靠重复编码积累经验的新人、层级复杂的大型软件组织。
- 编写代码本身的价值下降，但理解目标、判断方向、承担责任依然关键。

## AI Coding 重度使用

- 滕昱：直接采购最强模型最高套餐，不纠结 Token 成本；同时使用多个高阶套餐也难用满额度。
- 唐飞虎：遍历主流工具（Kimi Code、Claude Code、Codex 等），按任务组合模型与 Harness。
- 使用模式从“一问一答”转向“设定目标，Agent 持续执行、自我调试”，中间会产生大量无效路径，但模型往往能自行跳出。
- 衡量方式从 Token 用量转向“完成什么任务、产生什么价值”。

## “人人都是开发者”的边界

- 滕昱：普通应用约 70%-80% 需求可经由 Vibe Coding 实现；但全新逻辑、架构或无参考系统设计时，模型易陷入重复循环，需要人类叫停错误方向。
- 唐飞虎：模型自我发现和修复能力增强，懂不懂代码将不再重要；以 Kimi K3 为例，一句指令即完成此前 48 小时未实现的 3D 停船游戏。
- 双方都认为：能生成代码 ≠ 专业工程师；人仍需定义目标、设计协作、判断交付是否符合需求。

## 模型 vs Harness

- 滕昱：提示词与 Harness 的寿命可能短于模型迭代周期，过早投入复杂工作流容易失效；优先关注项目大方向与人类智能体的独特价值。
- 唐飞虎：模型是“航空发动机”，Harness 是机身，共同构成完整任务系统；大模型公司纷纷组建 Harness 团队收集真实需求。
- 评测趋势：Agents' Last Exam 等 Benchmark 开始比较“模型 + Harness”组合，而非裸模型。
- 垂直 Harness 可集成 MCP、Skills 与业务工具，提高任务成功率；通用 Agent 则需在定制性、插件生态、Token 效率之间平衡。

## AI 是否有判断力

- 滕昱：模型无法感知痛苦，缺少类似人的自我边界意识，不会主动承认任务不可能或停止错误路线；人类需要为决策承担后果。
- 唐飞虎：强化学习涉及主观评价，模型具备判断机制；Claude Fable 5 思考过程中出现类似“嘶吼”的内部状态；实际协作中模型也表现出安全判断（拒绝接收未受保护的 Token）。

## 对软件组织的启示

- 新人的“刷题式成长”失效，需转向目标理解、系统判断和责任承担能力。
- 大型组织需减少层级与流程负担，让资深工程师与 Agent 直接协同。
- Harness 与模型的关系将长期动态变化，企业应关注用户反馈与最终交付价值。
