# C语言尾调用优化讨论

LWN 上一篇关于 Python 尾调用与性能的文章引发了社区对 C 语言尾调用优化的讨论。评论指出，C 语言中的尾调用优化（TCO）并非历史悠久，其发展经历了曲折过程，并在现代解释器实现中扮演着越来越重要的角色。

## 历史背景

- 传统 C 调用约定中，被调用者不负责清理调用者压入栈的参数，调用者需在调用与返回之间自行清理栈帧，这使得尾调用难以优化。
- 1994 年，主流 C 编译器尚未对文章所示场景执行尾调用优化。
- 2001 年，Mark Probst 在 GCC 中实现了基于独立调用约定的尾调用优化，但存在诸多限制，如无法处理间接调用——而这正是解释器分派所需的场景。

## 近期进展

- 去年（约 2025 年）阅读的《Copy-and-Patch Compilation》论文使用了尾调用优化，促使作者重新测试 GCC 和 Clang，确认它们已能对文章所示的尾调用进行优化。
- Xu 和 Kjolstad 的方法可处理 10 万段代码片段，而 Gforth 基于 `goto *` 的实现仅限约 2000 段（用于 VM 指令、栈缓存变体、静态超级指令等）。尾调用优化若能支持 10 万级片段，将解锁更多技术。
- 因此，作者祝贺 Python 社区率先将这一能力用于实际解释器。

## 应用案例

### Forth 风格解释器

评论者 lafp 开发了一个 Forth 变体解释器，使用尾调用进行指令分派。主要收益是让所有内置函数本身表现得像指令，而不是经由“调用内置函数”指令间接执行；同时支持少量超级指令，显著提升性能。该项目最终目标是让用户通过浏览器控制 LED 矩阵。

### WebAssembly 解释器 Wasmi

评论者 Robbepop 表示，Wasmi 新版本大量使用直接线程化代码（尾调用）进行指令分派，也可配置为间接线程化或传统 switch 循环分派。基准测试显示，switch 循环与线程化代码之间存在巨大性能差异，因此现代高性能 Wasm 解释器（如 Wasmi、Wasm3、Stitch）都采用尾调用。

## 结论

尾调用优化如今被视作系统编程语言的基础能力之一。对于解释器、虚拟机等性能敏感场景，原生尾调用能显著减少分派开销，是构建高效运行时的重要工具。
