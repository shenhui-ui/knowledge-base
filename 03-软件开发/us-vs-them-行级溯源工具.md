# us-vs-them：基于版本历史的人类/AI代码行溯源工具

## 概述

`us-vs-them` 是一个开源库/CLI 工具，用于在**代理式编辑（agentic editing）**场景下，确定文本中每一行的来源——是人类编写，还是 AI 代理生成。它完全基于 Git 版本历史中的作者信息，通过 diff 算法推导出行级归属，而无需在文件中嵌入任何标记。

## 解决的问题

随着 AI 编码代理的普及，代码库中充斥着大量由模型生成的“slop”（低质量或不可控的代码）。人类手写的代码需要被视作“神圣不可侵犯”，代理在修改时应格外谨慎；而代理生成的代码则可以随意改写。例如：

- 一个大规模“vibecoded”应用，开发者希望在某些角落声明自己的所有权，避免代理在下一次会话中“推土机式”覆盖。
- README 等文档中，开发者重写了开头段落，但希望代理可以自由修改或追加后半部分，而不是随意改动开头。

该工具从版本历史中提取“人类岛屿”和“代理海洋”，为这种保护提供数据基础。

## 工作原理

核心思想：每个文本新版本都带有明确的作者标记（人类或代理）。通过对相邻版本进行简单 diff，计算连续区块的来源演变，从而得到一组范围（range）和“人类归属度”（human authorship score）。

输出示例：

```
1-3    0.00
4      1.00
5-7    0.00
8-20   0.46
21-164 0.00
```

- `1.0` 表示完全由人类编写的范围。
- `0.46` 表示最初由人类编写，但被代理修改到一定程度。
- `0.00` 表示完全由代理生成。

算法重点考虑合并、拆分、稀释等行为，避免结果收敛为全海洋或全岛屿，保持有意义的粒度。

## 使用方法

需要 [bbin](https://github.com/babashka/bbin) 进行本地安装：

```bash
make install
```

在任意 Git 仓库内使用：

```bash
us-vs-them --ours dan@eighttrigrams.net README.md
```

参数说明：

- `--ours`：指定人类作者的身份（其余均为代理）。
- `--theirs`：指定代理的身份（其余均为人类）。
- 两者同时传入会被拒绝。建议选择较短的名单传入。

## 意义与展望

该工具为 AI 辅助编程提供了一种细粒度的“所有权地图”，帮助开发者在人机协作中保留关键代码的决策权。未来可集成到 IDE 插件或 CI 流程中，作为代理修改代码前的自动保护层。
