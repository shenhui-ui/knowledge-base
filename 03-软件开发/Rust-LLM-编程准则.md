# Rust 项目采纳 AI 编程新准则：能帮你看，不能替你写

2026 年 8 月，Rust 项目中的编译器、标准库、类型系统、rustdoc 和 bootstrap 五个团队正式采纳了一项关于 AI 编程的新准则，用于规范贡献者在 rust-lang/rust 仓库中使用大语言模型（LLM）的行为。准则作者 Jynn Nelson 于 8 月 5 日在 Inside Rust 博客上宣布了这一消息。

## 核心原则

一句话概括：**可以用 LLM 回答问题、分析、提炼、完善、检查、提出建议和审查，但不能用它来创造。**

具体规则包括：

- 除非本人愿意，否则任何人都没有义务阅读 LLM 生成的内容。
- 未经明确标注，LLM 输出不得出现在公开文档、PR 描述或 GitHub 评论中。
- 审阅者有权拒绝审阅由 LLM 参与生成的 PR。
- 所有政策必须先写给人看，之后才能再整理成适合机器读取的版本。
- LLM 的审查结果不能代替人工审查，也不能代替作者自己的检查。
- 私下使用 LLM 且不对外发布时无需披露。
- 如果使用 LLM 进行机器翻译、微小修改、发现 Bug 或审查他人工作，必须披露 LLM 的参与。
- 欢迎贡献者使用自己的母语交流，不要求必须先翻译成英文。

## 使用分级

### 第一类：完全允许

只供贡献者本人查看的私人用途，例如：

- 向 LLM 询问代码库相关问题
- 总结讨论串
- 私下让 LLM 审查自己的代码

### 第二类：允许但必须披露

- 机器翻译
- 修复拼写错误等微小修改
- 借助 LLM 发现 Bug
- 使用 LLM 代码审查机器人（必须使用独立且明确标记的 GitHub 账号运行）

### 第三类：明确禁止

- 由 LLM 直接生成评论、文档和编译器诊断信息
- 任何必须依赖 LLM 才能运行的流程
- 仅凭 LLM 的审查结论就决定合并或拒绝改动

## 执行方式

故意隐瞒或虚假陈述使用 LLM 的情况，将被视为违反 Rust 项目《行为准则》，与骚扰行为同级。第一次违规可能警告，反复违规可能被封禁。

准则本身承认很多规定无法完全靠技术手段强制执行，这是有意为之：“我们的目标并不是抓住每一次违规行为……我们的目标，是消除任何可以推脱的空间：让人们必须在遵守准则和故意违反准则之间作出选择。”

## 与 Zig 的对比

Zig 的严格禁用 LLM / AI 规则更加彻底：不仅禁止 LLM 生成的代码和文字，也禁止改写或转述 LLM 内容，同时不允许使用 AI 做编辑、翻译、头脑风暴或找 Bug。Zig 方案执行成本低，但对贡献者来说遵守成本高；Rust 方案要求审阅者做更多判断，但也允许贡献者继续使用 LLM 工具。

## LLM 代码贡献实验与“熔断机制”

Rust 并没有彻底禁止 LLM 编写代码，而是将其限制在一个边界清楚的实验中：

- 任何由 LLM 创建的改动，必须提前和一名明确指定的审阅者沟通好。
- 这些改动不能涉及编译器健全性等关键部分。
- 必须有充分测试，也必须接受充分的人类审查。
- 无论什么情况，都必须披露 LLM 的参与。
- 新贡献者不能直接提交由 LLM 创建的 PR，必须先找到愿意负责审查的审阅者。
- 如果修改的代码部分原本没有测试套件，必须自己补上测试，否则只能关闭 PR。

**熔断机制**：如果在任意六周时间窗口内，已合并 PR 中超过一半是由 LLM 创建的，则所有 LLM 创建的 PR 将暂停合并，直到占比重新下降到 50% 以下，并至少冷却 10 天。六周周期与 Rust 的发布周期一致。

所有此类 PR 都会加上 `ai-assisted` 标签，并同步到私有 Zulip 频道，用于收集数据：例如使用 LLM 辅助的贡献者是否真的在学习、之后是否还会继续参与项目，以及最终能否持续产出有价值的工作。

## 制定原因

Nelson 提到三个压力促使规则正式化：

1. **信号失效**：结构完整、测试充分的 PR 不再代表作者投入了精力或真正理解代码，而 Rust 的代码审查文化过去依赖这种信任。
2. **审查资源紧张**：rust-lang/rust 仓库还有 1281 个未关闭的 PR，LLM 降低了代码生成成本，但没有增加审阅者的判断力和时间。
3. **劣化沟通**：一些贡献者把审阅者意见复制给 LLM，再把 LLM 回答复制回 GitHub，这是在浪费所有人的时间，也破坏了“审阅者是在和一个真实的人交流”的基础假设。

## 覆盖范围与例外

- 仅适用于 rust-lang/rust 仓库，且只约束已批准准则的团队。
- 不适用于 rust-lang 组织下的其他代码仓库。
- 不适用于语言团队的 Issue 跟踪、稳定性报告等工作。
- 风格指南不受约束。
- 尚未批准准则的团队不受约束。
- rust-lang 组织内部成员使用 LLM 创建代码时，可不受“不得修改关键代码”限制，但非常不鼓励使用该例外。
- 准则生效前已提交的 PR 不受约束。
- 即使有人违反 LLM 使用准则，也不能因其使用 LLM 而对其进行骚扰。

## 未来展望

第一个六周周期将帮助团队判断：允许一定范围内的 LLM 代码贡献，会不会进一步压垮合并队列。Rust 领导委员会还在讨论成立专门的 LLM 委员会，如果成立，其制定的项目级规则可覆盖当前准则，并可能扩展到聊天频道、论坛及其他代码仓库。
