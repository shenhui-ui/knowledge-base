# DoorDash 使用 Envoy 和 Valkey 构建 1.5M RPS 代理缓存

## 概述

DoorDash 开发了 Entity Cache，一个透明代理缓存平台，在微服务架构中减少对频繁访问但不常变更数据的重复请求。该平台基于 Envoy 和 Valkey 构建，支持 50 个服务的 100 多个端点，提供每秒超过 1.5M 请求量，可用性 99.99999%。

## 架构

Entity Cache 作为透明代理运行在 DoorDash 基于 Envoy 的服务网格内，拦截客户端服务和上游应用之间的 HTTP 和 gRPC 请求。它不要求服务修改应用代码，缓存行为通过服务网格集中管理，将缓存移动到基础设施层。

## 核心机制

- 缓存与失效：请求到达时检查 Valkey 是否存在有效缓存响应，命中直接返回，未命中则转发上游。使用基于 Kafka 的事件驱动失效机制，通过对比更新时间戳刷新过期条目。
- 双重 TTL 阈值：允许在故障期间返回略微过期的响应。
- 故障处理：Envoy 检测到不健康缓存实例时将其移除，并直接将请求路由到上游服务。

## 性能优化

- 自定义缓冲池降低内存分配开销
- 无锁 single-flight 机制防止缓存未命中时的重复计算
- 基于 XFetch 算法的概率性提前刷新，降低缓存雪崩风险

## 效果

优化将分配率降低了 50% 到 60%，每个 pod 的吞吐量提高约五倍，P99 延迟峰值降低最多 80%。报告显示缓存命中率超过 90%，正常运行期间上游请求减少 60% 到 95%，新接入端点延迟改善最高达 90%，P99 代理开销约 2.1 毫秒。在生产故障期间，Entity Cache 能持续提供略有过期但有效的缓存数据，避免服务失败。
