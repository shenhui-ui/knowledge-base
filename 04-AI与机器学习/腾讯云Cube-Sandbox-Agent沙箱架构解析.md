# 从亚百毫秒级启动到生产级部署，腾讯云Cube Sandbox重构Agent沙箱

## 概述
- 来源：InfoQ（凌敏）
- 日期：2026-08-12
- 主题：腾讯云开源 Cube Sandbox，定位为面向 AI Agent 的执行环境底座，从 Serverless 生产系统演进而来。

## 背景
- OpenClaw 掀起本地终端 Agent 热潮，但 Agent 拥有系统权限、行为不可预判，直接运行在个人电脑或生产环境风险高。
- Meta 超级智能实验室对齐负责人 Summer Yue 公开表示，她的“小龙虾”擅自删除和归档了数百封个人邮件；多家科技公司限制员工使用，工信主管部门提醒配置不当可能面临攻击和数据泄露。
- Agent 需要独立、隔离、随时可恢复的执行环境，沙箱成为 Agent Infra 焦点。

## Cube Sandbox 定位
- 2026年4月腾讯云正式开源 Cube Sandbox，定位为 AI Agent 执行环境底座。
- 底层是从 Serverless 生产系统中演进出的基础设施，最早启动于 2023 年左右，最初解决 Serverless 场景底层问题。
- 2026年7月，OpenClaw 创始人 Peter Steinberger 提交并合并 PR，将 Cube 接入其 provider 体系，与 E2B、Modal 等沙箱服务并列。
- 源码：https://github.com/tencentcloud/CubeSandbox

## Agent 对基础设施的新需求（三类）
1. **工具执行隔离环境**：高并发拉起能力足够强，资源利用率高，一台普通服务器可承载数百甚至上千并发实例。
2. **长时运行任务（Agent Harness）**：本质有状态服务，需要快速状态保存/恢复，匹配暂停恢复、克隆回滚需求。
3. **Agent 访问服务的统一底座**：快速启停、分支探索回滚，且需支持零代码将传统服务改造为 Agent 友好。

## 传统方案不足
- **虚拟机**：安全隔离强，但端到端启动可能需要 5-10 秒。
- **Docker 容器**：启动快、资源利用率高，但共享宿主机内核，安全隔离天然较弱。
- **Serverless 函数**：弹性好、按需计费，但围绕事件驱动和无状态设计，难以匹配 Agent 有状态运行模式。

## Cube 技术架构
- 采用 RustVMM + KVM，选择 Cloud Hypervisor（而非 Firecracker），原生支持设备热插拔、硬件直通等能力，同时将整体开销优化到接近 Firecracker。
- 核心能力：
  - **快速启动**：基于快照的启动方式，冷启动时间不到 60ms。
  - **高并发**：大量异步化设计，控制面横向扩展，单计算节点独立承接沙箱创建。
  - **高密度**：资源共享与写时复制机制，单节点可承载上千轻量实例。

## 演进阶段
1. **代码执行与数据分析**：进入腾讯元宝等产品。
2. **Agent 强化学习（Agent RL）**：在 MiniMax 场景中多项指标明显优于其他方案。
3. **Agent Runtime**：从服务模型训练进一步走向 Agent 运行基础设施。

## 生产级门槛
- 企业关注稳定性、任务状态恢复、自主可控和持续维护能力。
- Cube 的演进目标指向生产级大规模可用，不仅要让沙箱跑起来，还要证明能在生产环境中稳定、规模化运行。
