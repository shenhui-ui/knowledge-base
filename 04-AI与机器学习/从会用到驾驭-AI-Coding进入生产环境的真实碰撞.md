# 从“会用”到“驾驭”：AI Coding 进入生产环境的真实碰撞

> 本文整理自 InfoQ《极客有约》X AICon 直播，三位技术负责人：网易游戏高级技术经理林香鑫（主持人）、网龙网络资深技术总监陈洁、平凯数据库（TiDB）智能研发中心负责人柏佳辰、汇丰科技内部开源负责人李渭宁。

## 核心观点

- AI 进入生产环境后，不是减少人，而是更快赋能业务，业务需求大幅增加。
- 个人效率分化明显：技术功底好、认知高的人效率成倍提升；基础薄弱者反而造成混乱。
- 质量保障范式从“纺锤形”转向“哑铃形”：重视前端的 SPEC（需求规格）与后端的 Testing（测试验证），AI Coding Agent 类似自然语言编译器。
- 开发人员承担更多端到端质量责任，从逐行人工审查转向风险分级审查、自动化门禁和端到端验收。

## 生产环境落地变化

- **柏佳辰（TiDB）**：金融客户对遗留代码改造的需求大于新功能开发；组织层面的协同问题（不同人对 AI 工具适配性、熟练度不一致）会通过产品层暴露。
- **李渭宁（汇丰科技）**：业务需求增加，正在大规模招人；Dora Metrics 指标有所改善但难以直接归因；token 从订阅制转为计量消费，每人每月约几百美金预算，金融系统以精修为主，token 消耗不高。
- **陈洁（网龙）**：存在两种模式——规范工作流（结合 Claude Code、CodeX、Gemini CLI 与 Superpowers 方法论）和更激进的 YOLO Mode（Pilot Team 验证）。YOLO Mode 下团队会主动使用 Bypass Permissions，但该模式仅应在隔离容器/虚拟机/开发容器中使用，联网、数据库变更、生产操作等高风险动作必须走人工门禁。

## 质量保障范式转移

- 不再把逐行审查作为默认方式，而是风险分级审查 + 自动化门禁 + 端到端验收。
- 开发人员必须补足测试设计能力，将需求、完成条件和最终结果讲清楚、验到位。
- 复杂场景需显式编排任务依赖、分支、并行执行和状态流转（Loop Engineering）。

## MCP、Skills、Rules 的实践

- **陈洁**：正在建设 AI 能力中台与 Skill Hub，支持个人沉淀与治理发布；MCP 需要 Gateway 统一控制访问边界，并做敏感信息检测。CLAUDE.md 建议少于 200 行，任务型流程放入 Skills，路径约束放入 .claude/rules/；强制安全限制落到 permissions、Hooks 或工程门禁。
- **李渭宁**：目标是用 MCP、Skill、Rules 增强 AI 的动态可规划性和输出可控性。MCP 实践卡在数据权限控制，目前只能处理内部知识和项目 ticket；Skill 主要在开发环节，每个团队将开发规范、工作流、自动化包装成 Skill 复用；Rules 用于约束 AI 输出稳定性。最终期待的是在可控环境、可控流程中的稳定 Agent 输出，而非单一组件。

## 安全与权限治理

- 在可逆、低爆炸半径、可追溯的隔离环境内，按任务范围给 Agent 最小充分权限。
- 数据库结构变更、生产环境操作、外部网络访问等高风险动作严格收紧权限或设人工门禁。
- 每个 Agent 有身份标识，操作日志可追溯，持续纳入治理。
- “没有绝对的安全，都是发现问题快速亡羊补牢。”
