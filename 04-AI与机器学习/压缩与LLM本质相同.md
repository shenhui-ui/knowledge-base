# 压缩与语言模型：本质相同的任务

> 压缩器和 LLM 在核心层面尝试解决完全相同的问题。这篇文章将以直观方式讲解压缩的基本原理，并揭示它与语言建模之间的深层联系。

## 压缩如何工作

有很多方法可以缩小数据。例如 **minification**（精简）通过剥离代码到机器可解析的最小程度来工作：可读变量名缩减为单字母，空格和注释被移除。其理念是删除机器不需要的语法。

但真正的“压缩”依赖于**冗余**来压缩数据。考虑字符串：

`AAAAAAAAABBBBCCDAAADDDDDDDDD`

它包含 9 个 A、4 个 B、2 个 C、1 个 D、3 个 A、9 个 D，共 28 个字符。我们可以记录每个字符连续出现的次数：

`A9B4C2D1A3D9`

从 224 bits（28 字 * 8 bits）缩减到 96 bits（12 字 * 8 bits），压缩了 57%。这种技术叫**游程编码**（Run-Length Encoding）。

## 压缩器的解剖

现代压缩工具大致包含三个“器官”：

- **变换（Transforms）**：预处理步骤，使数据更容易被压缩。变换未必直接缩小数据，有时是为了创造更多冗余。例如游程编码就是一种变换。
- **模型（Models）**：基于每个符号的频率描述数据形状。可看作将每个符号映射到其概率的一张表。
- **熵编码器（Entropy Coders）**：几乎总是压缩流程的最后一步，负责产生最终压缩产物——原始比特流。

模型将概率交给熵编码器，熵编码器输出压缩后的比特流：

```
模型：符号概率
熵编码器：
输出：100101110
```

## 用概率压缩数据

每种熵编码器都各不相同，但它们在核心上都利用概率来压缩数据。以**算术编码**为例，它能很好地说明“更好的概率 = 更好的压缩”。算术编码将整个消息映射到 [0,1) 区间的一个实数，消息越长，区间越窄，所需比特数越接近信息熵。

## 与语言模型的联系

压缩和语言建模是同一枚硬币的两面。

- 语言模型的任务是预测下一个 token 的概率分布，这种概率分布正是构建压缩模型所需的核心信息。
- 反过来，一个强大的压缩器也必须内置对数据生成过程的理解，这本质上就是语言建模。
- 交叉熵与压缩率直接相关：交叉熵越低，理论上无损压缩能达到的压缩率越高。

因此，训练 LLM 的过程可以被视为在构建一个世界模型的压缩器。这也解释了为什么前沿 LLM 通常也是优秀的文本压缩器。
