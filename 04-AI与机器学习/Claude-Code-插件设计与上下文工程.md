# Claude Code 没有“魔法”：插件设计与上下文工程原语

> 来源：InfoQ，作者：傅宇琪 / Tina，2026-08-14

## 核心观点

- 如果 Claude 不能做所有你能做的事，它就无法和你一起做你的工作。我们并不是要取代自己，而是想成倍地放大自己。
- 定制化就是知识，定制化是在弥合模型天生所知与你们团队所知之间的差距。
- 钩子是唯一真正能扩展的插件抽象，不匹配就不注入，只在触发时才往上下文里放东西。
- 2026 年的核心转变是：从“把信息输入模型”转向“把信息从模型输出给用户”，人的注意力才是系统中最小的盒子。

## 从聊天机器人到 Agent

- 最初用 LLM 构建聊天机器人：人类说一句，模型回应一句。
- 2024 年出现工具调用（Tool Calls）：模型可以请求计算机执行操作、拿输出、做决策。
- 从零次工具调用到多次工具调用，跨过某个自主性边界后，被称为 Agent。
- 编码 Agent（Claude Code、Codex、Cursor）本质上是给 Agent 配备了程序员工具：文件编辑、CI、shell 命令。

## 工具调用的原始性

- 工具调用机制本质上就是：模型写 JSON → Harness 执行 → 结果塞回上下文。
- Claude Code 的编辑工具只是一个查找替换：旧字符串、文件名、新字符串，没有光标、没有选区、必须逐字节匹配。
- 模型在这种原始工具上的表现远超人类预期，但领域仍有大量迭代空间。

## Agent 的摩尔定律

- METR 图表显示：模型能以 50% 成功率完成的任务时间跨度，大约每四个月翻一番。
- 2026 年初趋势开始停滞，Opus 4.6 之后“什么算 16 小时任务”的误差范围太大，图表几乎不再有用。
- Mozilla 基金会 2026 年 4 月用最新模型修复的安全漏洞数量，超过过去 15 个月的总和。

## 为什么需要定制化

- 开箱即用的 Claude 只能看到一个代码仓库和一个 shell，甚至不允许走出启动文件夹。
- 这对零到一项目还行，但不足以在真正大规模范围内做高质量软件工程。
- 大多数专业软件工程并不存在于源代码里：团队聊天、CI、仪表盘、内部文档、设计文档。
- 建议：试着离开终端做一整天工作，如果你不能完成全部工作，Claude 也无法和你一起完成。

## 定制化就是知识

- 有些东西无法训练进模型：公司不同的 Conventions、机构记忆、内部 API、内部词汇、术语定义。
- 定制化的时髦术语是上下文学习（In-context learning），本质上就是文本文件。
- 模型权重在发布时冻结，几乎所有定制化都发生在文本层面。
- 程序员最擅长控制文本，不需要懂 LLM 权重的数学原理。

## 上下文工程的未来

- 当前 Claude 的工具调用水平大致相当于 Unix 的 ED 编辑器，与 VS Code 之间还有巨大鸿沟。
- 模型拿到的是纯文本，得不到富文本反馈，也没有实时反馈，需要自己补上机制。
- Claude Code 提供 post tool use hook：当 Claude 执行工具调用时，作为工具响应块的一部分，注入额外反馈。
- 这也是上下文工程的核心原语：只在触发时向上下文注入信息，不匹配就不注入。
