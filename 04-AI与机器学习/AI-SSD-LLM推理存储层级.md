# AI SSD 与 LLM 推理存储层级

## 背景与动因

大语言模型推理正同时撞上容量墙与 I/O 墙：

- 模型参数持续扩大，长上下文、多轮对话和智能体任务使 KV Cache 快速膨胀；
- MoE 模型虽降低单次激活参数量，却需保存远大于显存/内存容量的专家权重；
- 云侧 HBM 被模型权重和 KV Cache 长期占用，边缘侧有限 DRAM 限制本地模型规模。

SSD 因而从静态模型文件存放设备进入实时数据路径，成为 HBM/VRAM/DRAM 之外的一层正式存储层级。

已有产业实践包括：

- 月之暗面 Mooncake：以 KV Cache 为中心的分离式推理架构，将 GPU 集群中未被充分利用的 CPU、DRAM 和 SSD 组织为分布式缓存；Mooncake Store 支持 DRAM 与 SSD/NVMe 构成的多级缓存。
- 英伟达 CMX（2026）：在 Vera Rubin 基础设施中增加面向 KV Cache 优化的、通过以太网连接的闪存层级，由 BlueField-4 负责 NVMe SSD 管理，定义为介于 GPU 内存与共享存储之间的 pod 级上下文层。

## 传统 SSD 为何难以承担

- 传统 SSD 面向文件/块数据设计，指标围绕顺序带宽、随机 IOPS、可靠性与单位容量成本；
- LLM 推理需要严格时序的数据供应：KV Cache 在 prefill 阶段集中生成并持续写入，后续按会话/层/位置反复读取；MoE 需按路由结果及时取得专家权重；
- NAND 以页读、以块擦，FTL 的地址映射、垃圾回收和磨损均衡会造成写放大与尾延迟；
- 传统 LBA 排布不理解模型层、MoE 专家、KV 块与访问顺序的语义关系，端到端延迟难控。

## 两条技术路线

### 路线一：AI 负载强化型企业级 SSD

仍是块存储设备，但设计指标围绕 AI 数据路径重排。

**英韧科技洞庭 N3X**

- 采用 XL-Flash、SLC NAND 等低时延高耐久介质；
- 重点服务 KV Cache 卸载与高并发临时数据读写；
- 访问时延约降至传统 TLC SSD 的 1/3，写入吞吐提升约 3 倍，DWPD 提高约 17-33 倍；
- 规划向 PCIe 6.0 及 NVMe/CXL 双协议演进。

**华为 OceanDisk 系列**

- EX 560：极高随机写入性能、微秒级写入时延、高耐久，面向模型微调、检查点保存及高频缓存写入；
- SP 560：性能/耐久/成本平衡，面向 AI 一体机与集群推理中的 KV Cache、长上下文、多并发访问；
- LC 560：容量密度与顺序读取带宽优先，单盘最高 245TB，用于训练语料、多模态数据、向量库和大规模模型文件；
- 通过 DiskBooster 等驱动软件与 HBM、DDR 形成分层协同。

### 路线二：参与推理调度的 AI SSD

通过主控、固件、中间件及 OS/主板协同，建立近似“NAND Flash 与 DRAM/VRAM 联合虚拟化”的多级存储体系，使权重、MoE 专家和 KV Cache 在推理期间驻留 SSD，并按计算进度动态换入内存。

**群联 aiDAPTIV**

- 由 aiDAPTIVCache 专用缓存 SSD、内存管理中间件和工具链组成；
- 将超过 VRAM 容量的模型权重切块，在 VRAM 与 SSD 间流式传输，当前权重优先保留 VRAM，不活跃权重下沉 SSD；
- 保存可能被逐出的 KV Cache，上下文复用时从 SSD 回取，减少重新 Prefill 的开销；
- 专用缓存 SSD 耐久最高可达 100 DWPD，多个缓存 SSD 可提供 TB 级扩展内存空间；
- 通过整机厂商与渠道进入教育、科研、政府、企业私有化部署及本地微调市场。

**江波龙 SPU + iSA**

- WM8500 SPU 采用 5nm 工艺，集成存储控制、压缩、缓存和数据调度能力；
- iSA 感知推理负载，制定数据分层与预取策略；
- 支持存内无损压缩、HLC 高级缓存和混合 NAND 调度；
- 既可做消费级 AI SSD，也可扩展至企业级、工作站与端侧设备。

**联芸（Maxio）× 寅谱（Infplane）**

- 将寅谱推理芯片技术栈中的多级缓存、数据调度、并行搬运与预测式预取能力，与联芸的 NAND/主控/固件能力结合；
- 围绕 MoE 专家、KV Cache 和数值精度三个维度开展数据切分、冷热分层、并行搬运与预测式预取：一方面根据模型执行过程调度不同专家权重和 KV Cache，另一方面将模型文件的数值精度分为较热的低精度位和较冷的高精度位进行特殊的读写和存放；
- 以模型和推理框架兼容性为核心设计目标，在不修改模型文件、不侵入主流推理框架的条件下适配不同处理器平台，并降低对特定 SSD 模组形态的限制；
- 潜在价值在于，同时改善本地设备可承载的 MoE 模型容量、prefill 数据复用效率和 decode 阶段的数据供应；
- 相应代价是需要贯通 middleware、firmware 与 controller，软硬件协同范围更深，研发成本和工程验证难度也明显更高。

## 从单盘性能到系统协同，产业竞争才刚开始

不同 AI SSD 方案覆盖的技术层级并不相同：部分产品主要强化 SSD 介质与 I/O 能力，部分方案进一步参与模型权重、KV Cache 和 MoE 专家的运行时调度，而寅谱—联芸方案则试图贯通计算侧缓存体系、middleware、firmware、controller 与 NAND 介质管理。

从计算机制造商和智算基础设施厂商披露的信息看，群联与寅谱—联芸的方案都已不止于概念展示，正进入产品验证和商业化尝试阶段。其中，寅谱—联芸方案的验证范围已经不再局限于单一主控、单一模组或单一设备，而是向系统级协同方向扩展。

联芸已公开提出，AI 推理正在推动 SSD 主控从传统数据通道走向面向 Token 成本的智能调度；其横跨消费级、工业级和企业级市场的主控产品基础，也为相关技术进入不同 SSD 模组和整机形态提供了较大的产业化空间。
