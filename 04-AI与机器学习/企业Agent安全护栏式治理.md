# 企业Agent安全：护栏式治理与落地路径

> 本文整理自 AICon 全球人工智能开发与应用大会 2026 深圳站前夕的《极客有约》直播讨论，主持人为腾讯专家工程师、AI Agent 安全负责人张栋，嘉宾为百度智能云安全架构师林道正、Cloudflare 高级解决方案工程师刘旭。讨论聚焦 Agent 在企业核心场景落地时的运行时安全风险，以及如何实现安全可控的工程路径。

## 核心观点

- **安全不是刹车，是护栏**——有了护栏，在山路上反而敢开得更快。
- **human-in-the-loop 不是万能解药**——弹窗越多，越退化成 human clicking the button；真正的解法是把人只用在刀刃上。
- **安全与落地应同步演进**——渐进式管理，拒绝“完美主义延迟”。
- **安全方法论不变**：可视、可管、可追溯。
- **工具权限最小化**——危险的从来不是工具，而是我们给它的权限远超任务真正需要。

## Agent 为何越来越危险

- **行动能力是关键变量**：去年防的是“Agent 说错话”，今年 Agent 有了工具、记忆和执行权限，行为可能无人把关。安全本质从“内容对不对”换轨到“行为可不可控”。
- **传统 AI 是业务流中的一环，Agent 本身就是业务流**：Agent 掌控了业务流的全生命周期，影响更深。
- **攻击面从静态入口变为动态行为**：传统 AI 像自动售货机，Agent 像拿到公司工牌的新员工，会自己判断、找工具、联系人，防护边界变得难以界定。

## 企业真实踩过的坑

- **提示词注入仍是头号风险**：OWASP LLM 01 榜首。案例：员工用 Agent 总结邮件，黑客在邮件中隐藏指令，让 Agent 发送公司财报和老板薪水单。
- **数据注入**：搜索或查阅资料时，恶意内容可能被注入，曾有 Twitter 投毒导致 Agent 回复错误内容。
- **上下文压缩导致非预期执行**：上下文压缩后约束丢失，仅剩示例地址，Agent 可能将数据发送到伪造的示例网址（如 example.com）。
- **工具滥用与过度授权**：MCP 若授权 write 权限，提示词注入后可能导致合同被改等法律风险。

## 安全治理建议

- **工具层防护**：将工具置于沙箱隔离，给最小 API 权限、临时 token，在工具前加 gateway，并叠加 DLP 防护。
- **日志溯源**：即便所有防御失效，也要在各层面加日志，确保出问题时能溯源。
- **人机协同精准分工**：human-in-the-loop 只用于关键决策点，避免“闭着眼睛点确认”。
- **渐进式成熟度建设**：不必等做到完美才落地，安全应与产品迭代同步演进。
