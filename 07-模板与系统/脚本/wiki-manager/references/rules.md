# 知识库管理规则

> 本文件定义 wiki 知识库的完整运行规则。AGENTS.md 的精简版，便于在 LLM 上下文里直接引用。

## 目录语义

| 目录 | 性质 | 用途 |
|------|------|------|
| `00-收件箱/` | 只读 | 素材区，用户扔进来的原始材料 |
| `01-日记/` | 自由 | 每日笔记 |
| `02-资讯日报/` | 只读 | 工具只写区，AI 不读不写 |
| `03-软件开发/` | 可写 | wiki 主题区（软件开发） |
| `04-AI与机器学习/` | 可写 | wiki 主题区（AI/ML） |
| `05-数据分析/` | 可写 | wiki 主题区（数据分析） |
| `06-项目/` | 可写 | 项目区（仅项目相关文档） |
| `07-模板与系统/` | 系统 | 索引与日志在 MOC/ 下，禁入区：`.模板/`、`.obsidian/`、`脚本/` |
| `99-归档/` | 归档 | 已处理素材的归宿 |

## 命令

### ingest <素材>
1. 素材存为 `00-收件箱/<name> @manual.md`（手动流程加 @manual 后缀）
2. 读 `07-模板与系统/MOC/索引.md` 定位相关文章
3. 筛选：高价值/新主题 → 沉淀；重复 → 丢弃；广告/无内容 → 丢弃
4. 合并已有文章 or 新建到可写区
5. 索引按 Unicode 字母序插入 `[[文章名]]` 条目
6. 归档素材到 `99-归档/`
7. 追加操作日志到 `07-模板与系统/MOC/操作日志.md`

### query <问题>
1. 查索引定位文章
2. 读取命中文章
3. 基于 wiki 内容合成回答，引用具体页面链接

匹配策略（三层优先级）：
1. **子串优先**：文章名 ⊂ query
2. **关键词匹配标题**：query 中任意词 ⊂ 文章名
3. **非泛词搜索正文**：去掉泛词（模型/架构/预训练等）后命中正文

### lint
按 lint_rules 执行六项检查：
1. 索引 vs 实际文章（跨目录匹配）
2. 主题区分布
3. 链接目标存在性
4. 双向链接对称性
5. 索引 Unicode 顺序
6. 收件箱/归档状态

能安全自动修的（索引补漏、移除 MISSING 条目）直接修；
需判断的（矛盾、孤立页）报告。

## 安全边界

**可写**：03-软件开发 / 04-AI与机器学习 / 05-数据分析 / 06-项目 + 索引.md + 操作日志.md
**只读**：00-收件箱 / 02-资讯日报 / 07-模板与系统/附件/
**禁入**：07-模板与系统/.模板/ / .obsidian/ / 脚本/

修改 wiki 文件前先向用户确认。

## 命名与格式

### 文件命名
- 用中文描述性名（避免数字前缀），如 `RAG 检索增强生成.md`
- 含空格合法，但 lint **必须**用 Python/Node/Go（处理 UTF-8 + 空格），不得用 shell for 循环

### Wiki 文章 frontmatter
```yaml
---
type: ingest-note         # 必填
source: <原文链接或来源名>  # 必填
date: YYYY-MM-DD          # 必填
tags: [tag1, tag2]        # 推荐
---
```

### Wiki 文章正文
- H1 标题与文件名一致
- 内容来自源材料，去重/合并/提炼
- 末尾 `## See Also` 段，双向链接（`[[X]]` 形式）
- 每段 ≤150 字，避免大段引用

## lint_rules（YAML 配置）

```yaml
wiki:
  lint_rules:
    - "lint 必须用 Python/Node/Go 等能正确处理 UTF-8 与空格的工具，不得用 shell for 循环"
    - "能安全自动修的（索引补漏、移除 MISSING 条目）直接修，需判断的（矛盾、孤立页）报告"
```

详见 [`AGENTS.md`](AGENTS.md) 完整规则文件。
